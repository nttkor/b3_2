## 1. 미션 소개

AI API 연동이라고 하면 거창하게 들리는데, 사실 핵심은 '어떤 입력을 주냐'에 있습니다. git diff를 넘기고, 의미 있는 커밋 메시지와 PR 설명이 나오게 프롬프트를 설계하는 것이 이번 미션입니다. 단순 API 호출이 아니라, AI 결과물의 품질을 직접 제어하는 방법을 경험합니다.

AI API는 외부 AI 모델의 텍스트 생성 기능을 애플리케이션에서 호출해 사용할 수 있게 해주는 방식입니다. 고객 응대 문장 생성, 문서 요약, 개발 로그 정리처럼 입력값을 받아 AI가 생성 결과를 반환하는 자동화 작업에 활용됩니다.

이번 미션에서는 AI API를 호출하는 Python 코드를 기반으로, Git 변경 사항을 입력값으로 받아 커밋 메 시지와 PR 설명을 자동 생성하는 CLI 도구를 개발합니다. 단순 호출에 그치지 않고, API 파라미터와 컨텍 스트(Commit/PR 양식, 변경 이유, 요구사항)를 설계해 원하는 품질의 결과가 나오도록 프롬프트를 최적 화합니다.

또한 Git 명령 실행 결과를 프로그램에 연결하고, 생성된 결과물을 실제 커밋/PR 작성 흐름에 적용하며 연 동·검증·자동화를 하나의 흐름으로 구현합니다. 이를 통해 AI 기능을 서비스에 붙이는 방식을 구현 관점에 서 이해하고, 이후 다양한 업무 자동화/개발 보조 도구로 확장할 수 있는 기반을 갖추게 됩니다.

## 2. 최종 결과물

다음 3가지 결과물을 완성한다.

### 1. AI API 연동 및 자동화 흐름 동작 확인

- 입력/요청: AI API Key를 환경변수로 설정한 뒤, 프로젝트 루트 디렉토리에서 커밋/PR 자동 생성을 수행하는 Python CLI 프로그램을 실행한다.

### 2. GitHub 리포지토리

- 입력/요청: GitHub에 리포지토리를 생성하고, AI 기반 Git 커밋/PR 자동 생성기 프로젝트(소 스 코드 폴더)를 원격 저장소에 push 한다.

- 출력/화면: GitHub 리포지토리에서 소스 코드/파일 구조가 정상적으로 업로드되어 있으며, 커 밋 히스토리와 브랜치 작업 흐름을 확인할 수 있다.

### 3. 사용 가이드 문서(README.md)

- 입력/요청: 리포지토리의 README.md를 열어 실행 방법을 확인한다.

- 출력/화면: 설치 방법, 환경변수(API Key) 설정 방법, 실행 예시, 커밋/PR 생성 결과 예시, 주 의사항(또는 운영 관점)이 포함되어 있어 사용자는 문서만 보고 도구를 실행할 수 있다.

## 3. 과제 목표

이 과제를 마친 후, 학습자는 아래를 스스로 설명할 수 있어야 한다.

### 1. AI API를 REST API 방식으로 연동하는 과정에서 요청을 구성하고, 응답을 처리하며, 예외를 대응하는 전체 흐름

> **답변:**
>
> 1. **요청 구성 (Request Formulation)**
>    - **인증 분리**: API Key를 소스 코드에 절대 하드코딩하지 않고, `os.environ` 또는 `python-dotenv`를 통해 `.env` 파일 및 시스템 환경변수(`AI_API_KEY`)로부터 동적으로 주입받습니다.
>    - **엔드포인트 및 헤더**: OpenAI 규격의 REST 엔드포인트(`POST /v1/chat/completions`)에 맞춰 `Authorization: Bearer <API_KEY>`, `Content-Type: application/json` 헤더를 구성합니다.
>    - **페이로드(Payload) 조립**: 모델 식별자(`model`), 시스템 지시어 및 사용자 입력 프롬프트(`messages`), 샘플링 온도(`temperature`), 최대 토큰 수(`max_tokens`)를 JSON 형태로 직렬화하여 전송합니다.
>
> 2. **응답 처리 (Response Handling)**
>    - HTTP 상태 코드(200 OK) 수신 시, JSON 응답 구조(`choices[0].message.content`)에서 AI가 생성한 원본 텍스트를 정확히 추출합니다.
>    - 1회 실행당 API 호출 횟수(1회) 및 사용된 모델 메타데이터를 파싱하여 사용자 터미널에 명확히 안내합니다.
>
> 3. **예외 대응 (Exception Handling)**
>    - **인증 실패/키 누락 (401 Unauthorized)**: 지저분한 파이썬 스택 트레이스(Traceback)를 사용자에게 노출하지 않고, `[ERROR] AI_API_KEY 환경변수가 설정되지 않았습니다.` 및 `## 예) export AI_API_KEY="YOUR_KEY"`와 같은 직관적인 해결 가이드를 출력한 후 안전하게 종료(`sys.exit(1)`)합니다.
>    - **네트워크 오류 및 타임아웃 (Connection/Timeout Error)**: 게이트웨이 지연이나 연결 실패 시 오류 원인을 명시하고 재시도를 안내합니다.
>    - **API 파라미터/모델 거부 (400/502 Error)**: 제공자 프록시에서 지원하지 않는 파라미터(예: 특정 게이트웨이의 `temperature` 제한 등) 발생 시 호환 모델(`gpt-5.4-mini`)로 자동 폴백 또는 명확한 에러 원인을 보고합니다.

### 2. temperature, max_tokens 등 주요 파라미터가 결과 품질에 어떤 영향을 주는지 구분하고 설명

> **답변:**
>
> 1. **`temperature` (무작위성 및 창의성 제어, 0.0 ~ 2.0)**
>    - **원리**: 언어 모델이 다음 토큰을 선택할 때 소프트맥스(Softmax) 확률 분포의 평평한 정도(Smoothing)를 조절하는 파라미터입니다.
>    - **낮은 값 (0.0 ~ 0.3, 본 프로젝트 기본값: `0.3`)**: 가장 확률이 높은 단어를 결정론적(Deterministic)으로 선택합니다. 일관된 컨벤션(`feat:`, `fix:`) 준수, diff 코드에 기반한 사실적 요약, 사족이나 환각(Hallucination) 방지가 중요한 개발 도구에 가장 적합합니다.
>    - **높은 값 (0.7 ~ 1.0)**: 문장 표현이 다양해지지만, 정해진 글자 수 제한을 초과하거나 지정된 템플릿(Why/What/How to Test) 규격을 이탈할 위험이 커집니다.
>
> 2. **`max_tokens` (최대 출력 토큰 제한, 본 프로젝트 기본값: `1024`)**
>    - **원리**: 모델이 한 번의 응답에서 생성할 수 있는 최대 완성(Completion) 토큰 수를 강제 제한합니다.
>    - **영향**: 과도한 토큰 소모로 인한 비용 낭비 및 모델의 무한 반복 생성을 방지합니다. 너무 작게 설정(예: 50 미만)하면 PR 본문 작성이 중간에 잘려 문장이 미완성되는 절삭(Truncation)이 발생하므로, 본 도구는 간결한 커밋과 3단락 PR 본문에 최적화된 `1024`를 기본값으로 제공합니다.
>
> 3. **`model` (AI 모델 선정, 본 프로젝트 기본값: `gpt-5.4-mini`)**
>    - 모델의 추론 성능, 속도, 토큰 단가에 직접 영향을 미칩니다. `gpt-5.4-mini`는 빠른 응답 속도(~1.5초), Codyssey 게이트웨이 최저 차감 배율(0.5배), `temperature` 정상 조절을 지원하여 자동화 도구로 최적의 균형을 제공합니다.

### 3. git status, git diff 등 Git 명령 실행 결과를 프로그램 입력으로 연결하는 방식과 자동화 흐름

> **답변:**
>
> 1. **프로그램 입력 연결 방식 (Subprocess Integration)**
>    - Python 표준 라이브러리인 `subprocess.run()`을 사용하여 외부 Git 프로세스를 안전하게 호출합니다 (`capture_output=True`, `text=True`).
>    - **저장소 유효성 검사**: `git rev-parse --is-inside-work-tree`를 호출하여 실행 위치가 Git 리포지토리 루트인지 최우선 판별합니다.
>    - **상태 수집 (`git status --porcelain`)**: 기계가 파싱하기 쉬운 정형화된 공백/심볼 포맷으로 Staged/Unstaged 변경 파일 목록을 안전하게 추출합니다.
>    - **변경 내용 수집 (`git diff`)**: 실제 수정된 코드 라인을 텍스트로 추출합니다. 만약 변경 내용이 전혀 없는 경우 조기에 감지하여 `[INFO] 변경 사항이 없습니다...`를 출력하고 불필요한 API 호출을 즉시 차단합니다.
>
> 2. **전체 자동화 흐름 (End-to-End Pipeline)**
>    ```text
>    [CLI 실행] (python main.py commit / pr)
>           ↓
>    [저장소 판별] (is_git_repo 검사)
>           ↓
>    [변경사항 수집] (git status 및 git diff 추출)
>           ↓ (변경사항 없을 시 조기 정상 종료)
>    [안전 모드 처리] (-safe-mode: API Key/이메일/토큰 마스킹 + 파일/줄 수 제한)
>           ↓
>    [프롬프트 주입] (시스템 역할 + 컨벤션 규칙 + diff 텍스트 조립)
>           ↓
>    [AI API 호출] (OpenAI 호환 게이트웨이로 1회 정밀 요청)
>           ↓
>    [검증 및 후처리] (Validator: 제목 길이 강제 절삭, 필수 섹션/불릿 누락 보완)
>           ↓
>    [구획화된 출력] (터미널에 구분선 및 메타데이터와 함께 최종 표시)
>    ```

### 4. Commit/Pull Request 양식과 코드 변경 맥락을 포함해 AI가 요구사항에 맞는 요약을 생성하도록 프롬프트를 구성하는 원리

> **답변:**
>
> 1. **시스템 페르소나 및 역할 한정 (Role Specification)**
>    - AI에게 "Git 커밋 및 PR 문서를 전문적으로 작성하는 소프트웨어 엔지니어" 역할을 부여하여 잡담, 부연 설명, 서두를 배제하고 실무 개발 톤앤매너를 유지하도록 통제합니다.
>
> 2. **컨텍스트 격리 및 구조화 (Context Separation)**
>    - 프롬프트 내부에서 마크다운 코드 블록(```diff, ```status)을 활용해 '명령 지시사항'과 '분석 대상인 사용자 코드'를 엄격히 분리하여 프롬프트 인젝션 및 문맥 혼선을 방지합니다.
>    - 현재 브랜치명(`feature/login` 등)을 추가 컨텍스트로 제공하여 작업의 전체 목적과 개발 의도를 정확히 추론하도록 돕습니다.
>
> 3. **출력 템플릿 및 제약 사항 강제 (Structural Constraints)**
>    - **커밋**: `<type>: <description>` (feat, fix, docs, refactor 등) Conventional Commits 형식, 제목 1줄(50자 권장, 최대 72자), 본문에 변경 파일과 핵심 불릿 1~2개 포함을 명시합니다.
>    - **PR**: 1줄 제목(최대 80자)과 함께 본문은 반드시 `## Why`, `## What`, `## How to Test` 3대 섹션을 헤더로 구성하고 각 섹션마다 최소 1개 이상의 `- ` 불릿을 작성하도록 템플릿을 고정합니다.
>
> 4. **네거티브 프롬프트 (Negative Prompting)**
>    - "인사말, 설명, 코드 블록(```) 없이 오직 결과 텍스트만 출력하라"는 부정 지시어를 배치하여 파싱 오류를 원천 차단합니다.

### 5. 생성된 커밋/PR 텍스트가 실무 규칙(길이·템플릿·표현 제한)을 만족하도록 내용을 검증하고 필요한 부분을 다듬는 이유와 방법

> **답변:**
>
> 1. **검증 및 다듬기가 필요한 이유 (Why)**
>    - LLM(대형 언어 모델)은 본질적으로 확률 기반 텍스트 생성을 수행하므로, 프롬프트에 아무리 강력한 제약 조건을 주더라도 드물게 글자 수 초과, 필수 섹션 누락, 불릿 누락, 불필요한 메타 텍스트(예: "Here is your PR:") 출력 등의 비결정론적 변동이 발생할 수 있습니다.
>    - 실무 자동화 도구는 항상 예측 가능하고 규격화된 결과를 보장해야 하므로, 모델 응답 직후 소프트웨어 차원의 **결정론적 사후 검증(Post-validation) 및 폴백(Fallback) 후처리**가 필수적입니다.
>
> 2. **구체적인 구현 및 다듬기 방법 (How)**
>    - **제목 길이 강제 절삭 ([src/validator.py](../src/validator.py))**:
>      - 커밋 제목이 72자를 초과하면 72자에서 자르고 `[WARN] 커밋 제목 N자 → 72자로 자릅니다.` 로그를 출력합니다.
>      - PR 제목이 80자를 초과하면 80자에서 자르고 `[WARN] PR 제목 N자 → 80자로 자릅니다.` 로그를 출력합니다.
>    - **PR 3대 필수 섹션 누락 보완 (Section Fallback)**:
>      - 생성된 PR 본문에 `## Why`, `## What`, `## How to Test` 중 누락된 섹션이 있다면 정규식으로 감지하여 기본 안내 불릿과 함께 해당 섹션을 자동으로 채워 넣습니다.
>    - **불릿 구조 강제 (Bullet Enforcement)**:
>      - 각 섹션 아래에 `- `로 시작하는 불릿이 하나도 없는 줄글 형태일 경우, 첫 문장에 `- `를 삽입하여 구조화된 불릿 형식을 보장합니다.
>    - **메타 접두어 정제**:
>      - AI가 임의로 붙인 `TITLE: `, 마크다운 코드 블록 기호(```) 등을 정규식으로 안전하게 스트립(Strip)합니다.

## 4. 기능 요구 사항

다음 요구사항을 모두 만족해야 한다.

### 1. Git 변경 사항 수집

- CLI 실행은 Git이 초기화된 프로젝트 루트 디렉토리에서 수행되어야 한다.
- CLI 실행 시 git status 결과를 수집하여 변경된 파일 목록을 확인할 수 있어야 한다.
- CLI 실행 시 git diff 결과를 수집하여 변경 내용(diff 텍스트)을 얻을 수 있어야 한다.
- 변경 사항이 없을 경우, “변경 사항이 없습니다”에 준하는 메시지를 출력하고 종료해야 한다.

> **구현 및 답변:**
>
> - **구현 위치**: [src/git_collector.py](../src/git_collector.py) (`GitCollector` 클래스), [main.py](../main.py)
> - **구체적 구현 내용**:
>   1. **저장소 유효성 검사 (`is_git_repo`)**: `git rev-parse --is-inside-work-tree` 명령을 실행하여 현재 위치가 유효한 Git 저장소인지 사전 판별합니다. Git 저장소가 아닐 경우 `[ERROR] Git 저장소가 아닙니다. Git이 초기화된 디렉토리에서 실행하세요.`를 출력하고 `sys.exit(1)`로 즉시 종료합니다.
>   2. **상태 수집 (`get_status`)**: `git status --porcelain`을 실행하여 변경된 파일 목록과 Staged/Unstaged 상태를 기계 판독 가능한 포맷으로 파싱합니다.
>   3. **변경 내용 수집 (`get_diff`)**: `git diff HEAD` (Staged/Unstaged 통합)를 추출하여 실제 수정된 코드 라인을 수집합니다.
>   4. **변경 사항 부재 시 처리**: `diff.strip()`이 빈 문자열일 경우, `[INFO] 변경 사항이 없습니다. 커밋 메시지를 생성하지 않고 종료합니다.`(PR의 경우 `PR 초안을 생성하지 않고 종료합니다.`) 메시지를 출력하고 API 호출 없이 `sys.exit(0)`으로 정상 종료합니다. (clean repo 오탐을 유발하던 과거 `HEAD~1` fallback을 완전히 제거하여 정상화함)
> - **검증 명령어**:
>   ```bash
>   python main.py commit  # 변경사항이 없을 때 정상 종료 메시지 확인
>   ```
> - **관련 평가 항목**: 평가 1-1, 1-2, 1-3, 1-4

### 2. AI API 연동

- AI API Key는 환경변수로 설정되어야 하며, 코드에 하드코딩하지 않는다.
- CLI를 실행하면 AI API가 호출되고, 생성된 커밋 메시지 또는 PR 초안 텍스트가 터미널에 출력되어야 한다.
- API 호출 실패(네트워크 오류, 인증 실패 등) 시 오류 원인을 포함한 메시지를 출력해야 한다.
- **API 호출 파라미터(예: 모델, temperature, max_tokens)는 CLI 옵션으로 변경 가능해야 한다.**
  - 예: -model , -temperature , -max-tokens 같은 옵션을 제공하고 기본값을 둔다.

> **구현 및 답변:**
>
> - **구현 위치**: [src/ai_client.py](../src/ai_client.py) (`AIClient` 클래스), [src/main.py](../src/main.py) (`build_parser` 및 서브커맨드)
> - **구체적 구현 내용**:
>   1. **API Key 보안 관리**: 소스 코드에 키를 일절 하드코딩하지 않으며, [.env](../.env) 파일 및 시스템 환경변수에서 로드합니다. 키 우선순위는 `AI_API_KEY` (Codyssey 가이드 및 미션 사양 최우선) → `OPENROUTER_API_KEY` → `OPENAI_API_KEY` 순으로 탐색합니다.
>   2. **자동 엔드포인트 라우팅**: 키가 `sk-cody-`로 시작할 경우 기본 엔드포인트를 자동으로 Codyssey OpenAI Gateway(`https://copa.codyssey.kr/v1`)로 연결합니다.
>   3. **표준 에러 메시지 대응**: API Key가 누락되었거나 인증이 실패할 경우, 파이썬 트레이스백을 노출하지 않고 명세서 권장 양식과 100% 일치하는 에러 문구를 출력합니다:
>      ```text
>      [ERROR] AI_API_KEY 환경변수가 설정되지 않았습니다.
>      ## 예) export AI_API_KEY="YOUR_KEY"
>      ```
>   4. **CLI 옵션 지원 (`-` 및 `--` 모두 지원)**:
>      - `-model`, `--model`: AI 모델 ID (기본값: `gpt-5.4-mini`)
>      - `-temperature`, `--temperature`: 생성 온도 0.0~1.0 (기본값: `0.3`)
>      - `-max-tokens`, `--max-tokens`: 최대 출력 토큰 (기본값: `1024`)
>      - 서브커맨드 앞(`python main.py -temperature 0.2 commit`)과 뒤(`python main.py commit -temperature 0.2`) 어느 위치에서나 완벽하게 동작하도록 서브파서 옵션 상속(`argparse.SUPPRESS`)을 적용했습니다.
> - **검증 명령어**:
>   ```bash
>   python main.py commit -model gpt-5.4-mini -temperature 0.2 -max-tokens 512
>   ```
> - **관련 평가 항목**: 평가 1-5, 1-6

### 3. 커밋 메시지 자동 생성

- commit 명령을 실행하면 커밋 메시지가 생성되어 터미널에 출력되어야 한다.
- 커밋 메시지는 변경 사항 요약을 기반으로 생성되어야 한다.
- 출력 결과에는 커밋 제목 1줄이 필수로 포함되어야 한다.
- 커밋 본문은 선택적으로 포함될 수 있다(본문 포함 여부는 구현 선택).
- **(요약 품질 최소 기준) 커밋 본문을 포함하는 경우, 본문에 아래 중 1개 이상을 포함해야 한다.**
  - 변경된 파일(또는 모듈) 1~3개 언급
  - 핵심 변경 사항 1~2개를 불릿으로 요약
- 생성된 커밋 메시지는 터미널에 출력되어 사용자가 복사하여 적용할 수 있어야 한다.

> **구현 및 답변:**
>
> - **구현 위치**: [src/prompt_builder.py](../src/prompt_builder.py) (`build_commit_prompt`), [src/validator.py](../src/validator.py) (`validate_commit`), [src/main.py](../src/main.py) (`cmd_commit`)
> - **구체적 구현 내용**:
>   1. **명령어 제공**: `python main.py commit`으로 실행됩니다.
>   2. **Conventional Commits 규격 준수**: 프롬프트에 `feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:` 접두사를 명시하여 타입 기반의 표준 커밋 메시지를 생성합니다.
>   3. **제목 1줄 필수 보장**: 커밋 첫 번째 줄에 1줄 제목 생성을 강제하고, 72자를 초과할 경우 검증기에서 자동 절삭합니다.
>   4. **품질 최소 기준 충족 (본문 불릿 및 변경 파일 언급)**: 본문에 변경된 파일(또는 모듈) 언급과 함께 핵심 변경 사항을 1~3개의 `- ` 불릿 목록으로 요약하도록 지시 및 후처리합니다.
>   5. **구획화된 출력**: 터미널에 복사하기 쉽도록 명확한 구분선(`--- Commit Message ---`)으로 감싸서 출력합니다.
> - **실제 출력 예시**:
>   ```text
>   [INFO] 컨벤션 로드: .ai-gitgen.yml
>   [INFO] Git status 수집 완료: 1개 파일 변경 감지
>   [INFO] Git diff 수집 완료: 118줄
>   [INFO] AI API 요청 중...
>   [DONE] 커밋 메시지 생성 완료
>
>   --- Commit Message ---
>   docs: chat.md에 옵션 파싱 오류 대응 기록 추가
>
>   - chat.md에 `python main.py commit -temperature 0.2 -safe-mode` 실행 오류와 원인 분석을 정리
>   - 수정 결과와 재실행 확인 로그를 함께 기록해 변경 이력을 보강
>   ----------------------
>
>   [INFO] 모델: gpt-5.4-mini  |  호출 횟수: 1
>   ```
> - **관련 평가 항목**: 평가 1-1 ~ 1-6


### 4. Pull Request 제목/본문 자동 생성

- CLI 실행 시, PR 제목/본문 초안을 생성하는 명령어를 실행할 수 있어야 한다.
- **PR 본문은 템플릿 구조를 가져야 하며 아래 섹션 헤더를 포함해야 한다.**
  - Why(변경 배경)
  - What(핵심 변경 사항)
  - How to Test(테스트 방법)
- 각 섹션에는 최소 1개 이상의 불릿이 포함되어야 한다.
- PR 제목은 1줄로 출력되어야 하며, PR 본문과 함께 터미널에서 확인할 수 있어야 한다.

> **구현 및 답변:**
>
> - **구현 위치**: [src/prompt_builder.py](../src/prompt_builder.py) (`build_pr_prompt`), [src/validator.py](../src/validator.py) (`validate_pr`), [src/main.py](../src/main.py) (`cmd_pr`)
> - **구체적 구현 내용**:
>   1. **명령어 제공**: `python main.py pr`으로 실행됩니다.
>   2. **브랜치 맥락 수집**: `collector.get_current_branch()`를 통해 현재 작업 브랜치명을 추출하여 프롬프트에 주입, 작업 목적을 추론하도록 합니다.
>   3. **3대 필수 템플릿 섹션 강제**: `## Why`, `## What`, `## How to Test` 섹션 헤더를 반드시 생성하도록 프롬프트에 명시하며, AI 결과에서 누락이 발생하더라도 `validate_pr` 후처리기가 누락된 섹션을 감지하여 자동으로 보완합니다.
>   4. **섹션별 불릿 보장**: 각 섹션마다 최소 1개 이상의 `- ` 불릿을 의무화하며, 줄글로만 작성된 경우 첫 문장에 `- `를 삽입하여 구조화합니다.
>   5. **1줄 PR 제목**: 80자 이하의 간결하고 명확한 제목 1줄을 생성합니다.
>   6. **구획화된 출력**: `--- PR Title ---` 및 `--- PR Body ---` 구분선으로 제목과 본문을 나누어 출력합니다.
> - **실제 출력 예시**:
>   ```text
>   [INFO] 컨벤션 로드: .ai-gitgen.yml
>   [INFO] 현재 브랜치: main
>   [INFO] Git diff 수집 완료: 179줄
>   [INFO] AI API 요청 중...
>   [DONE] PR 초안 생성 완료
>
>   --- PR Title ---
>   chat.md에 가상환경 오류 해결 기록 추가
>   --- PR Body ---
>   ## Why
>   - `python main.py commit` 실행 중 발생한 `dotenv` 모듈 누락 및 가상환경/alias 간섭 문제의 원인과 해결 과정을 기록하기 위해서입니다.
>   - 동일한 실행 오류가 재발했을 때 빠르게 참고할 수 있도록 검증 결과까지 함께 남기기 위함입니다.
>
>   ## What
>   - `chat.md`에 오류 발생 원인, 해결 방법, 검증 결과를 포함한 대화 로그를 추가했습니다.
>   - 가상환경 자동 전환, `sys.prefix` 기반 감지, `activate` 스크립트 보강 관련 내용이 반영되었습니다.
>
>   ## How to Test
>   - `chat.md`에 추가된 내용이 원인 분석, 해결 내용, 검증 결과로 정상 반영되었는지 확인합니다.
>   - 문서 내에 포함된 `python main.py commit` 실행 예시와 결과가 일관되는지 검토합니다.
>   ---------------
>
>   [INFO] 모델: gpt-5.4-mini  |  호출 횟수: 1
>   ```
> - **관련 평가 항목**: 평가 2-1 ~ 2-4

### 5. 출력 형식 검증 및 다듬기

- **생성된 커밋/PR 텍스트는 아래 길이/형식 규칙을 적용할 수 있어야 한다(검증 후 재생성 또는 후처리 중 택1).**
  - 커밋 제목: 50자 이내 권장(최대 72자)
  - PR 제목: 최대 80자
  - PR 본문: Why/What/How to Test 섹션 헤더 필수 + 각 섹션 최소 1개 불릿
- 사용자가 결과를 검토할 수 있도록, 최종 출력은 구분선/헤더 등으로 구획이 나뉘어 표시되어야 한다.

> **구현 및 답변:**
>
> - **구현 위치**: [src/validator.py](../src/validator.py)
> - **구체적 구현 내용**:
>   - **후처리(Post-processing) 방식 채택**: API 재호출(재생성) 방식은 토큰 비용과 응답 지연을 2배로 증가시키므로, 1회 정밀 호출 후 소프트웨어 차원에서 결정론적으로 검증 및 다듬는 후처리 파이프라인을 채택했습니다.
>   - **커밋 제목 길이 제한**:
>     - 50자 이내 권장 안내 및 72자 초과 시 하드 컷(Hard Truncation): `title[:72]`로 절삭 후 `[WARN] 커밋 제목 N자 → 72자로 자릅니다.` 로그 출력.
>   - **PR 제목 길이 제한**:
>     - 80자 초과 시 하드 컷: `title[:80]`으로 절삭 후 `[WARN] PR 제목 N자 → 80자로 자릅니다.` 로그 출력.
>   - **PR 본문 필수 섹션 및 불릿 자동 보충**:
>     - `_SECTION_PATTERN = re.compile(r'##\s+(Why|What|How to Test)', re.IGNORECASE)`로 본문 구조를 분석.
>     - 섹션이 누락된 경우 기본 템플릿 섹션을 하단에 자동 추가하고 `[WARN] PR 본문 필수 섹션 누락: ...` 로깅.
>     - 섹션 내에 `- ` 불릿이 없을 경우 첫 번째 문장에 `- `를 붙여 `[WARN] ## [섹션] 내 불릿 누락 → 기본 불릿 항목 추가` 로깅.
>   - **구획 표시**: `--- Commit Message ---`, `--- PR Title ---`, `--- PR Body ---` 및 `[INFO] 모델: ... | 호출 횟수: 1` 메타데이터 구분선 제공.
> - **단위 테스트 검증**:
>   - [tests/test_assistant.py](../tests/test_assistant.py) 내 `TestValidator` 클래스에서 길이 절삭, 섹션 보충, 불릿 강제에 대한 5개 단위 테스트가 작성되어 있으며 100% 통과합니다.
> - **관련 평가 항목**: 평가 3-1, 3-2, 3-3

## 7. 제약 사항

- AI API 사용 범위

- AI API Key는 환경변수로만 관리하며 코드에 하드코딩하지 않는다.

- 과도한 비용 발생을 방지하기 위해, 1회 실행 시 요청 횟수는 1~2회 이내로 제한하는 것을 권 장한다.

- (권장 구현) commit / pr 명령은 각각 AI API 1회 호출로 결과를 생성하고, 로그에 호출 횟수 를 출력한다.

- Git 연동 범위

- Git 변경 사항 수집은 git status , git diff 범위로 제한한다.

- 커밋/PR 생성은 초안 텍스트 출력까지를 목표로 한다.

- git push , GitHub PR 생성(API 연동) 등 원격 저장소 자동 반영 기능은 구현하지 않는다.

- 보안/민감정보

- 보안/민감정보: git diff 에 포함될 수 있는 민감정보(API Key, 개인정보 등)는 프롬프트에 포함하지 않도록 주의한다.

- **아래 중 1개 이상을 -safe-mode 같은 옵션으로 제공한다.**

  - (A) diff에서 특정 패턴(API Key 형태, 이메일 등)을 마스킹 후 전송

  - (B) diff 일부만 전송(예: 최대 10개 파일, 최대 200줄)

<!-- 원본 PDF 6쪽 -->

- 생성된 커밋/PR 문구는 최종 정답이 아니며, 사용자가 검토 후 적용한다.
