# B3-2 평가 문항

> **미션:** 파일이 언제 어떻게 바뀌었는지 기록하는 작은 프로그램 만들기  
> **분야:** 자료구조와 알고리즘  
> **평가 범위:** 기능 동작, 자료구조·설계, 그래프 탐색·정렬·역색인, 확장성과 요구사항 변경 대응

각 문항을 확인한 뒤 충족한 항목에 체크합니다.

> **명령어 표기:** 미션의 CLI 문법에 따라 정렬 옵션은 `LOG --sort-by=date|author`로 통일합니다.

---

## 항목 1. 기능 동작 및 결과 확인

- [ ] `INIT <user_name>` 실행 후 `main` 브랜치, `HEAD`, 현재 사용자 설정이 정상적으로 초기화되어 있는가?
- [ ] `BRANCH <name>` 생성 후 `SWITCH <name>`으로 전환되며, 이후 `COMMIT`이 해당 브랜치에 반영되는가?
- [ ] `LOG`가 **부모 커밋이 자식 커밋보다 먼저** 출력되도록 동작하는가?
- [ ] `PATH <a> <b>`가 경로가 있으면 최단 경로를, 없으면 `No path`를 출력하는가?
- [ ] `ANCESTORS <hash>`가 모든 조상을 빠짐없이 출력하는가?
- [ ] `SEARCH <keyword>`, `SEARCH --author=<name>`, `LOG --sort-by=date|author`가 요구사항대로 동작하는가?

---

## 항목 2. 자료구조 및 설계

- [ ] 커밋 저장소, 브랜치, `HEAD`, 사용자 정보를 어떤 구조로 분리했고, 각 책임을 설명할 수 있는가?
- [ ] 커밋 hash로 빠르게 조회하기 위해 어떤 키-값 구조를 사용했고, 중복이나 충돌을 어떻게 방지했는지 설명할 수 있는가?
- [ ] 커밋이 추가될 때 역색인(`author`/`keyword`)을 어떤 시점에, 어떤 방식으로 갱신하도록 설계했는지 설명할 수 있는가?
- [ ] `LOG`, `PATH`, `ANCESTORS`에서 사용하는 그래프 탐색 로직을 어떻게 재사용 가능하게 구성했는지 설명할 수 있는가?
- [ ] 주요 함수와 클래스의 docstring 및 주석을 어떤 기준으로 작성했는지 설명할 수 있는가?

---

## 항목 3. 알고리즘 및 이론

- [ ] 커밋 그래프가 왜 DAG(Directed Acyclic Graph, 방향성 비순환 그래프)여야 하는지, 사이클이 생기면 어떤 문제가 발생하는지 설명할 수 있는가?
- [ ] `LOG`에서 **부모가 먼저** 조건을 만족시키기 위해 어떤 접근을 적용했는지 설명할 수 있는가?  
  `(예: 위상 정렬 성격의 출력)`
- [ ] `PATH`에서 최단 경로를 찾기 위해 어떤 알고리즘을 선택했고, 간선을 무방향으로 정의한 이유를 설명할 수 있는가?  
  `(예: BFS, Breadth-First Search, 너비 우선 탐색)`
- [ ] 직접 구현한 정렬 알고리즘의 평균·최악 시간복잡도와 안정 정렬 여부를 설명할 수 있는가?
- [ ] 역색인이 전체 순회 검색보다 빠른 이유를 자료구조와 시간복잡도 관점에서 설명할 수 있는가?

---

## 항목 4. 확장성과 요구사항 변경 대응

- [ ] 커밋 수가 10배 늘어났을 때 병목이 될 지점을 예측하고, 자료구조나 알고리즘 관점의 개선 방향을 설명할 수 있는가?
- [ ] `PATH`의 간선 정의를 **부모 방향만 허용**하도록 바꾸면 결과가 어떻게 달라지고, 구현에서 무엇을 변경해야 하는지 설명할 수 있는가?
- [ ] `LOG --sort-by=author` 요구사항이 **부모-자식 선후 관계도 유지**하도록 강화된다면 어떤 전략으로 해결할지 설명할 수 있는가?
- [ ] 해시 생성 방식을 카운터 기반과 난수 기반 사이에서 변경할 때 테스트, 재현성, 디버깅에 미치는 영향을 설명할 수 있는가?
